# نظام مبادرة ذات

تطبيق Next.js متكامل لإدارة تسجيل الطلاب بواسطة موظفي خدمة العملاء، مع لوحة مشرف، إرسال واتساب، سجل تدقيق، ونسخ احتياطية دورية.

## المسارات الرئيسية

- `/staff`: واجهة موظفي خدمة العملاء لتسجيل الطلاب، إنشاء الكود النهائي، تعديل الصلاحية، وإرسال الواتساب.
- `/admin`: لوحة المشرف لإدارة الموظفين، مراجعة الطلاب، متابعة السجلات، وتشغيل النسخ الاحتياطي.
- `/`: الواجهة الحالية للمبادرة ما زالت متاحة كما هي.

## إعداد البيئة

أنشئ ملف `.env.local` بالاعتماد على `.env.example` ثم أضف القيم التالية:

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_PASSWORD=
AUTH_SECRET=
DATA_ENCRYPTION_KEY=
WASENDER_API_KEY=
WASENDER_API_BASE_URL=https://www.wasenderapi.com/api
WHATSAPP_TOKEN=
CRON_SECRET=
SITE_ACCESS_PASSWORD=
```

`SITE_ACCESS_PASSWORD` هي كلمة المرور العامة التي تحمي جميع الصفحات مثل `/` و`/staff` و`/admin`.

### إعداد دخول الأدمن والموظفين على Vercel

- يجب ضبط `ADMIN_PASSWORD` لكلمة مرور المشرف.
- يجب ضبط `SUPABASE_SERVICE_ROLE_KEY` حتى تعمل صفحة `/staff` وتسجيل دخول الموظفين وإنشاء الحسابات.
- إذا كانت صفحة `/staff` تفتح لكن تسجيل الدخول لا يعمل، فغالبًا السبب أن `SUPABASE_SERVICE_ROLE_KEY` غير موجودة في بيئة Vercel.

تكامل الواتساب الحالي يعمل مع `WasenderAPI`:

- ضع `WASENDER_API_KEY` أو `WHATSAPP_TOKEN` بنفس قيمة `API Access Token` من جلسة Wasender.
- اترك `WASENDER_API_BASE_URL` على القيمة الافتراضية إلا إذا كنت تستخدم عنوانًا مخصصًا.

## ما الذي تم بناؤه

- تشفير بيانات الطلاب والموظفين الحساسة عبر AES-GCM داخل الخادم.
- جلسات آمنة للمشرف والموظفين عبر جدول `auth_sessions` وملف تعريف ارتباط `httpOnly`.
- جداول مستقلة للموظفين، الطلاب، السجل الرقابي، والنسخ الاحتياطية.
- إرسال رسالة واتساب تلقائيًا تحتوي على الكود النهائي، الدورات، المبلغ، الصلاحية، وبيانات الموظف.
- تشغيل نسخة احتياطية يدوية أو دورية مرة يوميًا عبر Vercel Cron بما يناسب خطة Vercel Hobby.

## إضافة موظف جديد

1. افتح `/admin` وسجّل الدخول بحساب المشرف.
2. من قسم `إضافة موظف جديد` أدخل:
   - اسم الموظف الكامل
   - رقم واتساب الموظف
   - الصلاحية الافتراضية للأكواد بالأيام
3. اضغط `إنشاء بيانات الاعتماد`.
4. سيقوم النظام تلقائيًا بإنشاء:
   - `رقم الموظف`
   - `معرّف الدخول`
   - `كود الربط`
   - `كلمة مرور مؤقتة`
5. سلّم هذه البيانات للموظف ليستخدمها في تسجيل الدخول إلى `/staff`.

## كلمات مرور الموظفين

- كلمة المرور لا تُكتب يدويًا عند الإنشاء؛ النظام يولد كلمة مرور مؤقتة تلقائيًا.
- الصيغة الحالية تبدأ عادةً بـ `Zat!` ثم أحرف وأرقام عشوائية لتكون سهلة نسبيًا وآمنة أساسيًا.
- الموظف يسجل الدخول باستخدام:
  - `معرّف الدخول` أو `رقم الموظف`
  - `كلمة المرور المؤقتة` التي تظهر فور إنشاء الحساب
- إذا احتجت لاحقًا ميزة تغيير أو إعادة تعيين كلمة مرور الموظف من لوحة الأدمن، يمكن إضافتها كتطوير مستقل.
